# 실행 지식

디버깅·반복 작업에서 피를 보고 얻은 것들이다.

## 빌드 함정

- **증상**: CLT 업데이트 후 `@State` 에서 `SwiftUIMacros.StateMacro` 플러그인을 못 찾아 컴파일이 실패하고, `build.sh` 가 먼저 이전 번들을 지우므로 실행할 앱도 사라진다.
  **원인**: CLT 기본 SDK 심링크가 호스트보다 새 베타 SDK(실측: MacOSX27.0.sdk)를 가리키면 SwiftUI 프로퍼티 래퍼가 매크로로 정의되는데, 매크로 플러그인 dylib 은 Xcode 에만 있고 CLT 에는 없다.
  **대응**: `build.sh` 가 호스트 macOS 메이저 버전과 같은 SDK 를 `SDKROOT` 로 고정한다. macOS 메이저 업그레이드 뒤 첫 빌드가 깨지면 이 항목을 먼저 의심한다. 그때는 Xcode 설치 또는 매크로 플러그인 경로 확보가 필요하다.

## 토큰 등록 사고 3종

- **오염된 토큰 저장**: 토큰 중간에 줄바꿈이 낀 채 Keychain 에 저장되면 `security` 가 값 전체를 hex 로 출력해 형식 검사가 실패하고 조용히 건너뛴다. 등록 명령의 클립보드 자동 정제와 파서의 자가 복원·길이 검사가 이중으로 막는다. 그래도 미연결이면 Keychain 값의 hex 여부를 먼저 본다.
- **파괴적 덮어쓰기**: 검증 전에 정제값을 원본 위에 덮어써 완전한 원본을 잃은 적이 있다. 오염이 의심되면 원본을 지우기 전에 정제값의 연결 성공부터 확인한다.
- **죽은 세션 토큰 고집**: `pgrep` 첫 매치(가장 오래된 프로세스)의 죽은 토큰만 계속 시도해 미연결이 이어졌다. 환경변수 토큰은 세션 단위라 프로세스가 남아도 창을 닫으면 무효화된다. "최신 프로세스 = 유효"도 성립하지 않으므로 후보 체인을 단일 선택으로 되돌리지 않는다.

## 파서와 집계의 비직관

- **`resets_at` 의 마이크로초 6자리는 표준 파서가 못 읽는다.** 소수부를 잘라낸 뒤 파싱한다. 형식이 바뀌면 게이지의 리셋 시각이 깨지므로 응답 스키마 변경의 첫 신호로 본다.
- **Codex 의 `primary`·`secondary` 위치는 파일마다 뒤바뀐다.** 한도 분류는 이름이 아니라 `window_minutes` 로 한다.
- **9월부터 prolite 응답은 `primary` 창 하나(10080분)만 담고 있다.** 5시간 창 기록이 없어 Codex 탭·개요의 5시간 게이지는 비어 보인다. limit 에러가 떴는데 7일 게이지가 낮으면 5시간 쪽일 가능성이 크다. 분류 규칙(`window_minutes` 기준)은 그대로 유효하다.
- **Codex 일별 귀속은 기기 로컬 시각 기준이며, 파일명 날짜가 아니다.** resume 으로 오래된 파일에 새 이벤트가 들어간다. 검증용 Python 이 UTC로 집계하면 일별이 1일 어긋나는데 Swift 쪽(기기 로컬)이 맞다.
- **Tuner 일별값은 130,000의 배수다.** `est_tokens = Δ(공식 주간 %) × 130K` 로 역산된 값이라 하루 단위 정확도는 로그 기준인 이 앱이 위다. Tuner 의 가치는 계정 전체(모든 기기+웹)를 본다는 데 있다.
- **스캔 중에도 로그가 계속 쓰인다.** 독립 Python 구현과 총합이 0.003% 이내로 어긋나는 것은 정상이며, 그 이상이면 스캐너를 의심한다.
- **주말·저녁에는 로컬 기반 주간 %가 공식보다 낮게 보인다.** 집 기기·모바일 사용(월 계정의 약 15~20%)이 로컬 로그에 없기 때문이다. 다른 컴퓨터 로그를 통째로 복사해 설정의 추가 경로에 넣으면 합산된다. 같은 요청이 양쪽에 있어도 중복 제거가 걸러내므로 이중 계상되지 않는다(사본 병합 테스트로 검증됨).

## 반복 작업 체크리스트

- **수치를 바꾸는 수정 뒤**: `./build.sh` 재빌드 → headless 스캔으로 총합 확인 → 독립 Python 구현과 대조(0.003% 이내) → 앱에서 해당 탭 육안 확인. 화면 캡처 검증이 안 되면(사용자 거절 등) 기하 계산으로 겹침·잘림을 코드 리뷰로 확인하고 그 사실을 작업 기록에 남긴다.
- **공식 API 관련 수정 뒤**: 저장해둔 실응답으로 파서 단위검증 → 미분류 버킷 0건 확인 → 429를 만났는지 확인. 새로 캡처가 필요하면 1회만 요청한다.
- **요율표 수정 뒤**: 분기 대조(공식 요금 페이지) → 퇴역·단종 모델의 0원·제외 처리 확인 → 화면의 비용 캡션 문구와 일치 확인.
