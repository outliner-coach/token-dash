# Claude 사용량 대시보드 (네이티브 Swift)

`~/.claude/projects/**/*.jsonl` 로컬 세션 로그를 직접 파싱해 토큰 사용량과 추정 비용을
보여주는 SwiftUI + Swift Charts macOS 앱. 외부 의존성 없음.

```bash
./build.sh && open build/ClaudeUsage.app
```

Xcode 없이 Command Line Tools 의 `swiftc` 만으로 `.app` 번들을 만든다.
앱 안에서 ⌘R 또는 우측 상단 새로고침 버튼으로 재스캔한다 (2,400여 파일 / 2.2GB 를 약 3초).

## 탭

| 탭 | 내용 |
|---|---|
| 개요 | KPI 5종, **실시간 한도 현황(5시간 블록 · 주간 전체 · 주간 Fable 3게이지)**, 모델별 일간 스택 막대, 일별 추이, 연간 합계 |
| 프로젝트 | 프로젝트별 순위 (비중 막대 / 요청 수 / 출력 / 토큰 / 비용) |
| 모델 | 모델 구성 도넛 + 모델별 토큰 종류 구성 + 순위표 |
| 세션 | 토큰 많은 순 세션 상위 150개 (기간·주 모델·세션ID) |
| 일별 | 전체 기간 막대(최고일 표시) + 일자별 상세 표 |
| **Codex** | `~/.codex/sessions` 집계 — 로그에 박힌 공식 한도 게이지(5시간·7일) + 모델·프로젝트·일별 |

## 파싱에서 반드시 지켜야 하는 두 가지

로그를 그냥 줄 단위로 합산하면 결과가 크게 틀린다. 실측으로 확인한 두 가지 함정:

**1. 한 요청이 여러 줄에 중복 기록된다.**
하나의 API 응답이 content block 개수만큼 줄로 쪼개져 저장되고, 각 줄이 **같은 usage 를
그대로 복사**해 갖는다. 20.8만 줄 중 11.5만 줄(55%)이 중복이다.
→ `message.id + requestId` 로 중복 제거. 안 하면 2배 이상 부풀려진다.

**2. 단, `output_tokens` 만은 마지막 줄에만 최종값이 있다.**
앞선 줄들은 `out=1`, `out=5` 같은 부분값을 갖는다. 그래서 "첫 줄만 채택" 방식으로
중복을 제거하면 **출력 토큰의 17.9% 가 누락**된다 (표본 9,239 그룹 검증).
→ 같은 키에서 `output_tokens` 는 최대값을 채택. `input`/`cache_*` 는 전 줄이 동일해 무관.

**서브에이전트 경로 주의.** 디렉터리 구조가 두 가지다.

```
<프로젝트>/<세션UUID>.jsonl                     ← 메인 세션
<프로젝트>/<세션UUID>/subagents/agent-*.jsonl   ← 서브에이전트 (1,810개)
```

부모 디렉터리 이름을 그대로 프로젝트로 쓰면 서브에이전트 사용량 38.8억 토큰이
`subagents` 라는 가짜 프로젝트로 새어 나간다. 프로젝트는 항상 **첫 번째** 경로 요소,
세션은 **두 번째** 요소로 잡아 부모 세션에 합산한다.

## 비용 계산

100만 토큰당 USD. 캐시 요율은 입력가 대비 배수 (쓰기 5분 1.25x / 1시간 2x, 읽기 0.1x).

| 모델 | 입력 | 출력 |
|---|---|---|
| Fable 5 / Mythos 5 | $10 | $50 |
| Opus 4.x | $5 | $25 |
| Sonnet 5 | $2 | $10 (2026-08-31 까지 도입가) |
| Sonnet 4.x | $3 | $15 |
| Haiku 4.5 | $1 | $5 |

`<synthetic>` 등 가격표에 없는 항목은 0으로 처리하고 표시에서 제외한다.
Anthropic 구독 요금제 사용자라면 실제 청구액이 아니라 **API 정가 환산 추정치**다.

## 두 가지 단위 — 한도(출력) vs 분석(총 처리)

이 앱은 목적이 다른 **두 지표**를 명확히 나눠서 쓴다. 개요 화면에도 각각 색 배너로 구분한다.

| 용도 | 단위 | 어디에 |
|---|---|---|
| **한도 관리** | **출력 토큰** | 개요 상단 KPI(5시간·주간 사용률) + 실시간 한도 게이지 |
| **사용 분석**("어디에 얼마나") | **총 처리 토큰**(입력+캐시+출력) | 오늘/이번달 KPI, 모델별·일별 차트, 연간 합계, 프로젝트/모델/세션/일별 탭 |

### 왜 출력 토큰인가 — Claude 한도의 실제 단위

처음엔 raw 총계(캐시읽기 포함)로 한도를 쟀는데, Claude 설정·Claude Tuner 수치와 **~190배** 어긋났다.
일별로 대조해 보니 Claude 의 플랜 사용량 한도는 **출력 토큰** 기준이었다:

```
최근 7일 총량:  Claude Tuner 12.3M  ↔  앱 출력 토큰 12.5M   (오차 1.3%)
가장 많이 쓴 날: Tuner 4.8M(화)      ↔  앱 출력 4.4M
```

raw 총계는 캐시읽기가 96%라 한도와 무관한 방향으로 부풀려져 있었다. **한도 게이지는 출력 토큰,
분석 차트는 총 처리 토큰** 으로 분리한 이유다.

**단, 출력 토큰은 "작동하는 근사"이지 공식 계량 단위로 확정된 것이 아니다.** 주간 총량은 일치하지만
일별로는 Tuner 와 크게 어긋나고(집계 경계·계정 단위 차이), 서로 다른 시점의 보정이 함의하는 한도값도
±20~30% 흔들린다(5시간: 12% 앵커 → 3.47M vs 37% 앵커 → 4.33M). 내부 계량은 비용 가중 + 계정 단위
(타 기기 포함)로 추정된다. 게이지가 잘 맞는 이유는 단위를 알아서가 아니라 **공식 %에 앵커**했기 때문 —
모델 믹스가 크게 바뀌면 오차가 커지므로 주기적 재보정을 권장한다.

### 공식 사용률 직접 연결 — Tuner 방식의 완성형

Tuner 의 본질이 "공식 %의 스냅샷"이라면, 이 앱은 변환 없이 **공식 %를 직접 읽는다**.
Claude Code 의 `/usage` 가 쓰는 OAuth 엔드포인트(`api.anthropic.com/api/oauth/usage`)를
30분 간격(레이트리밋 시 지수 백오프 최대 60분, ⌘R 즉시 갱신)으로 폴링해, 게이지의 %와 리셋 시각을 **계정 정본**으로 채운다.

- **토큰 출처** (읽기 전용, 저장·전송하지 않음 — 우선순위 순):
  ⓪ **전용 장수명 토큰** — 공식 OAuth 흐름인 `claude setup-token` 으로 발급해 앱 전용
  Keychain 항목에 등록. 실행 중인 세션에 기대지 않아 Claude 를 꺼도 연결이 유지된다:
  ```bash
  claude setup-token        # 브라우저에서 본인 승인 → 토큰 출력 → 토큰을 드래그해 ⌘C 복사
  security add-generic-password -a "$USER" -s ClaudeUsageDashboard-token -w "$(pbpaste | tr -cd 'A-Za-z0-9_-')" -U
  ```
  두 번째 명령은 클립보드에서 줄바꿈·공백·유니코드 잔여물을 자동 제거한다(터미널 줄바꿈 복사 사고 방지).
  앱 쪽 파서도 hex 덤프·개행 낀 값을 자가 복원하므로 이중 안전장치다.
  (config.json 평문 저장은 지원하지 않는다 — Keychain 만.)
  ① 실행 중인 Claude 프로세스의 `CLAUDE_CODE_OAUTH_TOKEN` 환경변수(세션이 떠 있으면 존재)
  ② Keychain `Claude Code-credentials` (만료 검사 통과 시).
  참고: Tuner 의 Google 로그인은 **Tuner 자체 서비스** 인증이다. Anthropic 사용량은 Google
  계정으로 읽을 수 없고, Tuner 도 결국 어딘가에서 Claude 자격증명으로 수집한다 — 그 폴링이
  이 엔드포인트의 계정 레이트리밋을 나눠 쓰는 것으로 추정된다.
- **역할 분담**: 공식 % = 게이지 링·리셋 시각(계정 전체, 모든 기기 합산) / 로컬 로그 = 토큰
  수치·프로젝트·모델 세부("어디에 얼마나"). 두 값의 차이(공식 vs 로컬 추정)는 게이지에 함께 표시돼
  다른 기기 사용량이 그대로 보인다.
- **미연결 시** (Claude 세션 없음, 토큰 만료, 레이트리밋): 아래 보정 추정치로 자동 폴백하고
  주황색 안내를 띄운다. 응답 스키마는 "utilization" 필드를 가진 객체를 전부 수집하는 관대한
  파서로 처리하며, 분류 안 된 버킷 키는 화면에 노출해 스키마 변화를 바로 알 수 있게 했다.
- 엔드포인트 레이트리밋이 길다(실측 10분+, 같은 계정의 다른 클라이언트(예: 집 기기의 Tuner)와 한도를 공유하는 것으로 추정). 429 를 받으면 물러났다가 재시도한다.

### 한도는 어떻게 아는가 — 보정(calibration, 공식 % 미연결 시 폴백)

Anthropic 은 한도 토큰 수를 공개하지 않으므로, 앱이 보여주는 **사용률(%)을 출력 토큰으로 역산**한다:

```
한도(출력 토큰) = (그 시점 출력 토큰 사용량) ÷ (앱 표시 %)
```

Max 20x 실측값: **주간 ≈16.2M(타기기 보정) · 5시간 4.33M · Fable ≥2.46M(로컬 하한)**.

- **재보정**: 앱의 현재 %를 알려주면 그 시점 출력량으로 다시 역산. 큰 %(예: 주간 50%대)일수록 정확.
- **직접 편집**: `~/.config/claude-usage/config.json`.

```json
{
  "plan": "Max 20x",
  "weeklyResetWeekday": 4, "weeklyResetHour": 18,   // 목 18:00 리셋
  "limitWeeklyAll": 16200000,   // 출력 토큰 (87% 앵커 + 타기기 보정)
  "limitFiveHour": 4328384,
  "limitWeeklyFable": 2461504
}
```

### 창(window) 정의

- **5시간 블록**: 첫 요청 시각을 정시로 내림해 시작, 5시간 경과 또는 5시간 이상 공백 시 새 블록.
  Claude 의 활동 기준 5시간 한도와 같은 방식(스크린샷의 11:00–16:00 과 일치).
- **주간(전체·Fable)**: 리셋 요일·시각(목 18:00)으로 고정된 7일 창. 스크린샷의 "7/23 오후 6시 리셋",
  "7/30 리셋(166h)" 과 일치.
- **Fable**: 정책 문구는 "주간 한도의 최대 50%". 실측 도달점(출력 2.46M, ≈정가 $755)은 단위에 따라
  주간의 **20%(출력)~30%(비용)** 로 어느 단위로도 50%에 못 미친다. {Fable 100%, 주간 87%, 캡 50%}가
  동시에 성립하려면 Fable 비중이 57.5%여야 하는데 모든 실측 단위에서 미달 — 원인은 (a) 실효 캡이
  50% 아래("최대"는 상한 문구, 전환기), (b) Fable 을 정가 이상으로 가중하는 내부 계량, 중 판별 불가.
  게이지는 실측 절대량(2.46M)을 분모로 쓰므로 어느 쪽이든 추적은 유효하다.
- 사용률 100% 초과 시 링 안쪽에 얇은 빨간 링으로 초과분 표시.

### 검증 — Tuner API 7월 일별 대조 (period=1..25 차분)

Tuner 는 로컬 로그가 아니라 **공식 계정 카운터(%)의 스냅샷 기록기**다. 결정적 증거: 일별값
25개 중 23개가 정확히 **130,000의 배수** — 즉 `est_tokens = Δ(공식 주간%) × 130K`, Tuner 가
가정한 Max 20x 주간 한도 = 13M 토큰이다. 일별 숫자는 스냅샷 귀속이라 하루 단위로는 이 앱(로그
타임스탬프)이 더 정확하고, Tuner 의 가치는 **계정 전체(모든 기기+웹)를 본다**는 데 있다.

7월 한 달(6/29~7/23)을 일별 차분으로 대조한 결과:

- **총합**: Tuner 40.97M vs 로컬 36.43M → +4.54M (마지막 2일 스냅샷 지연 -2.9M 감안 시 실질 +7M대)
- **원격(집 기기/모바일) 확정일 11일**: 주말(7/04·11·12·18·19), 금요일(7/03·17), 평일 저녁(7/02·14·20·21)
  — 일 0.3~1.4M 규모. 전날 로컬 잔여로 설명되는지 드리프트 반증 테스트로 걸러냄.
- 최근 7일 총량이 0.3% "일치"했던 건 원격 사용(+2.9M)과 스냅샷 지연(-2.9M)이 **우연히 상쇄**된 것.

→ 주간 한도 재역산(87% 앵커에 원격분 포함): `0.87W = 로컬 10.51M + (원격 2.88M/13M)·W` →
**W ≈ 16.2M** (Tuner 가정 13M, 범위 14.5~17.5M). 원격이 주말·저녁에 몰리므로 로컬-만 게이지는
그런 시간대에 공식보다 낮게 표시된다.

### 한계 — 로컬 로그만 본다 → 다른 컴퓨터는 병합 가능

이 앱은 기본적으로 이 컴퓨터의 `~/.claude/projects` 만 읽는다. 공식 %는 **계정 전체**(모든 기기+웹)라서,
다른 기기 사용량이 커지면 로컬 기반 보정은 한도를 하한으로 잡게 된다.

**다른 컴퓨터의 로그는 병합할 수 있다.** 그 컴퓨터의 `~/.claude/projects` 를 통째로 복사해 오고
(`rsync -a othermac:~/.claude/projects/ ~/claude-logs-other/` 또는 AirDrop), config 에 경로를 추가:

```json
{ "extraRoots": ["~/claude-logs-other"] }
```

같은 요청이 양쪽에 있어도 (message.id+requestId) 중복 제거가 걸러내므로 이중 계상되지 않는다
(사본 병합 테스트로 검증). 모바일/웹 사용량은 로컬 로그가 없어 여전히 사각지대다.

## Codex 탭

`~/.codex/sessions/**/*.jsonl` 을 읽어 Codex(OpenAI) 사용량을 따로 보여준다. **Claude 수치와
합산하지 않는다** — 토큰 필드의 의미가 다르기 때문이다:

| | Claude | Codex |
|---|---|---|
| 캐시 읽기 | input 과 **배타적** (따로 더함) | `cached ⊂ input` (**더하면 이중 계상**) |
| 합계 | input+캐시쓰기+캐시읽기+output | `total = input + output` |
| 기록 방식 | 요청당 절대값 (중복 줄 존재) | **세션 누계** (증가분만 더해야 함) |
| 한도 정보 | 별도 OAuth API 필요 | **로그에 이미 포함** (`rate_limits`) |

마지막 항목이 특히 좋다 — Codex 는 응답마다 계정의 공식 사용률(5시간/7일 %, 리셋 시각,
plan_type)을 로그에 남기므로 토큰·레이트리밋 걱정 없이 그대로 읽어 쓴다. 단 "마지막 사용
시점"의 값이라, 그 뒤 다른 기기에서 쓴 분량은 반영되지 않는다.

비용은 표시하지 않는다 (gpt-5.x 공식 요율 미확인).

| `TimeUtil.swift` | DateFormatter 없이 고정 포맷 ISO8601 처리 (days_from_civil) |
| `Model.swift` | 집계 타입, 가격표, 5시간 블록, 주간 창·한도 역산 |
| `Config.swift` | 한도 설정·보정(JSON, `~/.config/claude-usage/config.json`) |
| `Format.swift` | 억/만 한국식 축약 |
| `Theme.swift` | 다크 테마 색상, 카드/KPI 컴포넌트 |
| `App.swift` / `OverviewView.swift` / `RankView.swift` / `DailyView.swift` | UI |

DateFormatter 와 `JSONSerialization` 을 쓰지 않는 이유는 순전히 속도다.
20만 줄에 Foundation 파서를 돌리면 스캔이 수십 초로 늘어난다.

## 검증

Swift 바이트 스캐너와 별개로 작성한 Python(`json.loads`) 구현의 결과가
총합 기준 0.003% 이내로 일치한다 (차이는 스캔 중에도 세션 로그가 계속 쓰이기 때문).
